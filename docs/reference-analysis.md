# Reference investigation: swarm-cursors / Swarm Rebuild

Investigated public `DhvanilPatel/swarm-cursors` at commit `eef4b5e38dcfe30064d5272d8ce5ee738d855f80` (2026-11-17). Read-only source investigation. No reference implementation, assets, or animation code copied into SwarmWatch. README's License section explicitly says “None yet” and asks readers not to reuse code without checking with the upstream author as well. README also says its motion engine adapts Joel Califa's Swarm site. These restrictions apply to both sources; our implementation must remain independent.

## Evidence and behavior

- **DOM/layout snapshot:** `swarm-rebuild/swarm.js:491 captureModel` walks live DOM through `walk` (1018), gets computed styles through a per-capture Map cache, captures `getBoundingClientRect`, converts world versus viewport coordinates, tracks clipping, opacity, position, stacking and scroll containers. `kidsOf` (225) includes open shadow roots. `cloneStyled` (329), `prepClone` (263) and pseudo-element helpers copy computed presentation into inert clones. `detectEnv` (1553) handles document versus inner scrolling. This is a one-time visual blueprint, not ongoing mutation tracking or source/component mapping.
- **Task decomposition:** snapshot produces rect/text/image/line items, then `captureModel` builds `tasks` (1267–1386). Child box tasks depend on the parent; repeated sibling groups found by `findGroups` (1220) use tag/class/layer/kind signatures and similar dimensions. Duplicates depend on master completion, followed by text edits, image swaps or restyling. These are visual layers rather than React component or agent tasks.
- **Cursor movement/flocking:** `Engine.moveTo` (2566) is distance-based, eased movement with a curved offset; generator primitives consume frame deltas. `follow` (2460) steers cursors around an orbit target, blends neighbor velocities, limits speed and avoids the mouse. `flock` (2438) introduces decorative cursors for the finale. Cursor counts grow with scrolling/backlog (2370); they do not correspond to real agents. SwarmWatch should only use real attributed identities and keep unknown activity off arbitrary components.
- **Rectangle/resize:** `drawBox` (2701) moves a crosshair to the top-left and drags toward the bottom-right, growing live selection dimensions. Large boxes clamp drag endpoints to the viewport, then finish dimensions. After the placeholder, the styled box/image appears. `selection` (2253) supplies corner handles, dimension badges and ruler lines; `View.renderOverlay` (1964) renders SVG selections and measurements.
- **Text:** `prepText` (1399) decomposes cloned text into units while preserving inline formatting and treats atomic elements as one unit. `reveal` (1448) reveals a prefix. `type` (2605) advances units using a variable timing budget. `drawText` (2768) draws a text region, changes to I-beam, types, optionally steps a heading up from 18px, and snaps to guides. It does not observe real typing or AI intent.
- **Images/media:** `mediaFor` (832) supports image/SVG/video/canvas/iframe representations. `background.js` temporarily hides non-media and uses Chrome `captureVisibleTab` after an authorized click, then `cropShot` (405) extracts pixels inaccessible through DOM. `drawBox` renders a placeholder followed by a reveal. Below-viewport media may remain placeholders; autoplay lacks screenshot privilege. A web dashboard cannot assume extension privileges and should keep the live iframe intact.
- **Guidelines/duplicates:** snapshot groups shared left edges/baselines into up to 16 guide tasks (1316–1367). Generator `dragGuide` and `duplicate` animate ruler dragging and option-drag copying, with spacing marks in `renderOverlay`. These are inferred choreography based on an existing completed page, not evidence that an agent duplicated an element.
- **Scheduler/queue:** `Engine.available` (2268) checks waiting state, dependency completion and scroll frontier; `pick` (2282) prefers viewport/top tasks and nearby cursor positions, giving guides priority. `step` (2310) adjusts tempo from scroll velocity and backlog, assigns a task generator per cursor and advances generators until done. Replay recaptures/rebuilds a completed page; `App.loadShot` (3506) reuses the click-time screenshot. It is not a persisted development history.
- **Performance:** hard caps: 4,000 items / 40,000px world (`swarm.js:39–40`), 8–48 work cursors (35–36), 36 finale cursors (37). Snapshot style cache, document fragments in mounting (1751+), item version counters (`renderItem`, 1808; early return at 1820), cached cursor shape DOM, cached SVG/badge output, transform-based cursor placement and `will-change`, isolated contained shadow host. Single `requestAnimationFrame` loop (`App.frame`, 3699) clamps dt at 50ms; HUD updates every 200ms. Flocking remains pairwise in active cursor count. No event ingress backpressure or reconnect persistence exists.

## Boundary for independent SwarmWatch

Reusable **ideas**, not source: measured bounds; item-specific pointer states and selection affordances; per-identity animation queues; requestAnimationFrame timing; viewport-aware coordinates and bounded work. New work required: file watcher, secure local transport, stable normalized events, source provenance/confidence, Vite source instrumentation, MutationObserver/ResizeObserver bridge, HMR correlation, real agent adapters, persisted session sequencing and honest replay limitations. The reference's whole-page blanking, inert cloned application, synthetic swarm counts and snapshot-derived build order must not be used as proof of live agent work. SwarmWatch should retain the actual interactive iframe and animate non-destructive overlays only for observed deltas.
